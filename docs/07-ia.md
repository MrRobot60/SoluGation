# Intelligence artificielle

## Principe

L'IA est **facultative**. Sans configuration, SoluGation fonctionne entièrement : les boutons IA sont masqués, on évalue à la main, le rapport reçoit un texte factuel automatique, EBIOS RM se mène sans propositions.

Quand elle est configurée, l'IA **propose** et un humain **valide** : chaque conclusion, recommandation ou proposition naît « à valider ». Aucune ne vaut décision d'homologation.

| Fonction | Ce que l'IA reçoit | Ce qu'elle produit |
|---|---|---|
| Analyse des documents | Le **texte des documents déposés** (extrait localement) et la liste des mesures | Couvert / partiel / absent par mesure, avec citations vérifiées mot pour mot |
| Recommandations | Exigence, constat, tâche, contexte du projet (pas les documents) | Étapes, preuve à fournir, effort |
| Rédaction du rapport | Chiffres du projet, sans aucun nom de personne ni d'organisation | Sections du rapport, chiffres non retrouvés signalés |
| Propositions EBIOS RM | Éléments déjà saisis, désignés par des clés courtes, sans entité responsable | Événements redoutés, biens supports, couples SR/OV, scénarios |

Le texte d'une norme payante (ISO) n'est jamais envoyé.

## Responsabilité de l'administrateur

**Le choix du fournisseur et de ses conditions relève de l'administrateur de l'installation.** Avant d'activer, vérifiez dans le contrat (DPA) du fournisseur :

- la **conservation** des données envoyées (idéalement aucune : « zero data retention ») ;
- l'**usage pour l'entraînement** (doit être exclu) ;
- la **localisation** des traitements et la juridiction applicable ;
- la compatibilité avec la sensibilité des documents de vos organisations.

L'activation exige de cocher l'acceptation de cette responsabilité ; elle est datée, nominative, tracée au journal, et **redemandée** à chaque changement d'adresse, de modèle ou de clé.

## Configurer depuis l'écran (recommandé)

Compte administrateur de l'installation → **Administration** → **Intelligence artificielle**.

1. **Préremplir** : Scaleway, Mistral, OpenAI, Ollama (réseau local) ou Autre.
2. Renseignez **Nom affiché**, **Modèle** (identifiant exact du fournisseur), **Adresse de l'API** (se termine en général par `/v1`), **Clé d'API**.
3. **Enregistrer**, puis **Tester la connexion** : un message minimal, sans aucune donnée de projet.
4. Cochez **J'accepte la responsabilité de ce choix**, puis **Enregistrer et activer**.

La clé est **chiffrée** en base et n'est jamais renvoyée au navigateur (seuls ses 4 derniers caractères s'affichent). Laissez le champ vide pour la conserver. **Désactiver l'IA** revient à la configuration du fichier `.env` (ou à « aucune IA »).

Chaque **organisation** peut ensuite refuser l'IA pour elle-même : Administration → organisation → « Autoriser l'IA pour cette organisation ».

## Configurer par le fichier `.env`

```dotenv
IA_FOURNISSEUR=compatible
IA_NOM=Mon fournisseur
IA_URL=https://api.fournisseur.eu/v1
IA_MODELE=nom-du-modele
IA_CLE=...
IA_ZDR_CONFIRME=True      # acceptation de la responsabilité
```

Raccourcis : `IA_FOURNISSEUR=scaleway` (adresse et modèle par défaut, `IA_CLE` requise) ou `mistral` (variables `MISTRAL_*`). Puis `docker compose up -d`. L'écran Administration indique « Fournisseur défini dans le fichier de configuration ».

## Exemples de fournisseurs

| Fournisseur | Adresse | Remarque |
|---|---|---|
| Scaleway Generative APIs | `https://api.scaleway.ai/v1` | Hébergement en France, conservation zéro par défaut selon sa documentation. Modèle par défaut `mistral-small-3.2-24b-instruct-2506`. |
| Mistral | `https://api.mistral.ai/v1` | Conservation 30 jours par défaut ; le « zero data retention » se demande au support. |
| OpenAI | `https://api.openai.com/v1` | Hors UE ; vérifier les options de conservation. |
| Ollama (local) | `http://ollama:11434/v1` | Rien ne sort de votre réseau. Requiert `IA_AUTORISER_RESEAU_LOCAL=True`. |
| vLLM, LM Studio… | selon déploiement | Toute API compatible OpenAI (`/chat/completions`, mode JSON). |

Ces exemples sont indicatifs : les conditions des fournisseurs changent, vérifiez-les vous-même.

## Une IA locale avec Ollama

Ajoutez un service à `docker-compose.yml` (ou utilisez un Ollama existant sur le réseau) :

```yaml
  ollama:
    image: ollama/ollama
    volumes:
      - ollama:/root/.ollama
```

(et `ollama:` sous `volumes:`), puis :

```bash
docker compose up -d ollama
docker compose exec ollama ollama pull mistral-small3.2
```

Dans `.env` : `IA_AUTORISER_RESEAU_LOCAL=True`, puis à l'écran : adresse `http://ollama:11434/v1`, modèle `mistral-small3.2`, sans clé. Prévoyez une machine avec suffisamment de mémoire (un modèle de 24 milliards de paramètres demande plus de 16 Go) ; un modèle plus petit fonctionne mais propose moins juste.

## Protections intégrées

- **SSRF** : une adresse saisie à l'écran ne peut pas viser le réseau interne, la boucle locale ou les métadonnées cloud ; HTTPS obligatoire ; contrôle à l'enregistrement **et à chaque appel** ; redirections jamais suivies. Levée seulement par `IA_AUTORISER_RESEAU_LOCAL=True`.
- **Injection de consignes** : le contenu des documents est présenté comme une donnée ; la sortie est filtrée (seules les mesures, tâches ou clés demandées sont acceptées, cotations bornées).
- **Hallucinations** : une conclusion sans citation retrouvée dans le document est écartée ; un chiffre de rapport absent des données est signalé.
- **Traçabilité** : chaque analyse et chaque décision sur une proposition sont au journal d'audit.

## Coûts

Une analyse de documents d'un projet moyen consomme de l'ordre de 50 000 à 300 000 tokens ; une rédaction de rapport, quelques milliers. Avec un petit modèle, c'est généralement moins d'un centime par opération ; vérifiez la grille de votre fournisseur.
